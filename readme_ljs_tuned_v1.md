# 비인기지 보상 가중치 밸런싱 — EDA 초안 (M3 선행)

## 1. 작업 개요

상위 문서: [readme_ljs_v1.md](readme_ljs_v1.md) (비인기 앵커 선택 로직)
대상: `WEEKLY-PLAN.md` §2 이지선 — "(M3 선행) 혼잡도 → 비인기지 보상 가중치 밸런싱 데이터 초안"

`app/scenario/density.py`에 이미 존재하는 STUB:

```python
def reward_weight(tier: str) -> float:
    """비인기지 보상 가중치(분산 유도). 실수치는 EDA로 확정."""
    return 1.5 if tier == "low_traffic" else 1.0
```

이 함수는 현재 코드 어디에서도 호출되지 않는 orphan 상태다(실제 보상 시스템 자체가 아직 없음).
이 문서는 그 "1.5"라는 임의값의 근거를 종로 실측 데이터로 검토하고, M3에서 보상 로직을 붙일 때
참고할 밸런싱 초안을 제시한다. **코드 변경 없음 — 데이터 분석 문서만.**

## 5. 보상 가중치 밸런싱 초안

`avg_cnctrRate`를 4구간(quartile)으로 나눠 가중치를 제안한다. 현재 `reward_weight()`는
tier 이진값(`low_traffic`/`popular`)만 받으므로, 이 표는 **향후 연속·다단계 가중치로 확장할 때**의
초안이며 지금 당장 코드에 반영하는 것은 아니다.

| 구간 | avg_cnctrRate 범위 | 라벨(제안) | 가중치(제안) |
|---|---|---|---:|
| Q1 | ≤ 52.15 (p25 이하) | 매우 한산 | 2.0 |
| Q2 | 52.15 ~ 63.10 | 한산 | 1.6 |
| Q3 | 63.10 ~ 70.92 | 보통 | 1.3 |
| Q4 | > 70.92 (p75 초과) | 혼잡 | 1.0 (= popular) |

근거:

```text
- Q4 하한(70.92)은 현재 density_lowtraffic_max_avg_rate와 동일 → 지금의 "popular"
  판정과 정합성을 유지.
- 현재 STUB 1.5는 Q2~Q3 사이에 위치 → "low_traffic" 태그가 Q1~Q3를 뭉뚱그린 이진값이라는 점을
  감안하면 크게 벗어난 값은 아니지만, Q1(매우 한산)과 Q3(컷오프 근처)를 동일하게 1.5로 취급하는 건
  "분산 유도"라는 목적에는 다소 느슨함.
- 가중치 값(2.0/1.6/1.3/1.0) 자체는 이번 표본(113개, 단일 시점) 기준 제안치이며,
  실제 보상 정책(포인트/코인 단위) 확정 시 M3에서 재조정 필요.
```

## 6. 연속형 확장 옵션 (참고, 미구현)

이산 tier 대신 연속 함수로 갈 경우의 방향만 기록한다(구현 아님):

```text
weight(avg_rate) = 1.0 + max(0, (max_avg_rate - avg_rate) / (max_avg_rate - min_avg_rate)) * (W_max - 1.0)

- max_avg_rate = density_lowtraffic_max_avg_rate(70.9, 현재 popular/low_traffic 경계)
- min_avg_rate = 분포 min(이번 표본 20.51) 또는 p5 등 완충값
- W_max = 정책으로 결정할 최대 가중치(예: 2.0)
```

전제 조건: `select_lowtraffic_anchors`가 선택 시점에만 알고 있는 `avg_rate`를 node에
남겨야 함(예: `node["cnctr_rate_avg"] = avg_rate`). 이건 `density.py` 안에서 가능하지만,
그 값을 실제로 소비하는 보상 로직은 generator 쪽 영역이라 **김예슬(kys) 통합 시점에 조율 필요**.
