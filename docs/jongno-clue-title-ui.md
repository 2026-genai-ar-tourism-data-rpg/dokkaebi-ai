## 0. 배치 위치가 다르다는 점 먼저
`design-m3.md`는 **탐험 준비 단계**(홈·탐험·라이브러리·도감, "AR 화면 구현"은 명시적 제외)를 다룬다.
단서함·칭호는 반대로 **플레이 중**(AR/퀘스트 진행 화면)에 뜨는 바텀시트라 스코프가 다르다 — v3
standalone 프로토타입의 "힌트 시트"·"컬렉션 시트"와 같은 급의 in-play 모달로 붙는 게 자연스럽다.
Flutter 개발 담당(kys, `app-v3-back`)이 이 문서를 참고해 AR 플레이 화면 쪽에 배선하면 된다.

## 24. 단서함 (Clue Inventory)

플레이 중 획득한 단서(申時 / ㄱ / ㅏ 등)를 모아보는 바텀시트. 다음 노드에서 무엇을 뜻하는지
복기하는 용도 — 즉 게임 진행에 실제로 쓰이는 인벤토리(`단서_설계_규칙.md`: "단서가 실제 수행
조건으로 쓰임").

### 단서 카드 상태
- 획득
- 미획득(잠금)
- 방금 획득(신규, 진입 애니메이션)

### 획득한 단서 — 표시 정보
- 단서 이름(짧은 텍스트/한자, 예: `申時`) — `단서_설계_규칙.md` 이름 규칙(2~5글자) 그대로 카드 라벨
- 획득 노드/장소(예: "운현궁")
- 단서 획득 시 대사 1줄 다시 보기(예: "먹빛은 찾았으나 아직 글자가 차갑구나...")
- 이 단서가 다음에 어디서 쓰이는지 안내(예: "익선동에서 확인해 보거라" — 소프트 requires 안내,
  `시나리오_구조화.md` 규칙 1조 "데드락 금지"와 동일한 안내형)

### 미획득 단서 — 표시 정보
- 실루엣 + `???`
- 카드 순번만 표시(예: "두 번째 단서")
- 해금 힌트 없음(단서 자체가 다음 노드로 가는 힌트이므로, 스포일러 방지를 위해 미획득 상태에선
  아무 텍스트도 노출하지 않음 — `design-m3.md`의 도감 "해금 힌트" 패턴과 의도적으로 다름)

### 진입 경로
- AR/퀘스트 플레이 화면 상단 HUD의 단서함 아이콘 → 바텀시트로 열림
- 총 단서 수는 `docs/jongno-baseline-v1.1.md` 기준 고정값(申時·ㄱ·ㅏ = 3개)이 아니라, `design-m3.md`
  도감과 동일하게 서버가 내려주는 `totalCount`를 씀(다른 지역 확장 시 개수가 달라지므로 하드코딩 금지)

## 25. 칭호 (Title)

`design-m3.md`에서 명시적으로 제외됐던 기능. 종로 클리어 시 획득하는 칭호(`jongno-baseline-v1.1.md`
피날레 보상: "종로의 글지기")를 두 곳에 노출한다 — ① 플레이 중 상단 HUD 라벨, ② 획득 시 알림 모달.

### 25-1. HUD 칭호 라벨
- 표시 정보: 현재 칭호명(없으면 기본값, 예: "이름 없는 탐사자"), 진행 중인 챕터 번호
- v3 standalone 프로토타입에 이미 있던 HUD 라벨 자리를 그대로 재사용(임시값 "글지기 견습" →
  실제 칭호 체계로 교체)

### 25-2. 칭호 획득 모달 (`design-m3.md`의 CouponModal과 동일 패턴)
#### 칭호 획득
- 제목: 칭호를 얻었어요!
- 내용: 「종로의 글지기」 — 잊혀진 글씨를 되살린 자
- 버튼: 도감에서 보기 / 확인

### 25-3. 내정보(Profile) 탭 — 칭호 목록
- `design-m3.md` 하단 내비게이션의 "내정보" 탭에 칭호 목록 섹션 추가 제안(현재 문서엔 Profile
  화면 상세가 없어 이 문서에서 최소 스펙만 보강)
- 표시 정보: 보유 칭호 목록(획득 지역·날짜), 현재 대표 칭호로 설정(선택 가능)

### 상태
| 컴포넌트 | Variant |
|---|---|
| TitleBadge(HUD) | default(기본값) / equipped(칭호 있음) |
| TitleAcquiredModal | shown / dismissed |
