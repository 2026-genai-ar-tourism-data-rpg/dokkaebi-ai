결함 01 치명 담당: AI 실제 LLM 전용 · mock 미재현

도깨비가 대사 대신 프롬프트 규칙을 읽어 줍니다

증상
앱이 보내는 본문 그대로 POST /v1/scenarios를 호출하니, 노드 4개 중 3개의 npc_dialogue에 프롬프트 지시문이 섞여 나왔습니다. 이 값은 QuestNode.npcDialogue로 앱 화면에 그대로 표시됩니다.
실측
— 민영환 자결터 
허허, 이 자리가 바로 민영환 선생이 을사늑약의 치욕을 견디지
못해 충절로 목숨을 바친 곳이라니라. … 헤아리지 않겠느냐?
[규칙 준수]
- 순국 장소·혈죽 유래·조형물 요소(유서·단검) 등 실제 정보만 기술
- "~니라" 어미와 감탄사 "허허" 적용
- 3문장으로 장소 소개 + 가벼운 질문 구성

   "백성들" 등 추정 표현 삭제)

… 남산 팔각정도 이를 본받았겠다!
(장소 정보에 근거해 역사적 사실과 건축적 특징을 강조하며,
 감탄사와 거친 어말어미 '~느니라/~겠다'를 유지)
원인
결함 2의 오탐이 대사를 반려하면서, 재생성 프롬프트에 _FB_HALLUCINATION(“근거 밖 표현: 감탄사, 3문장, …”)을 실어 보냅니다. solar-pro가 그 지시를 대사 본문에 복창합니다. 유출된 텍스트에 감탄사·3문장·어말어미처럼 피드백 문구에만 등장하는 단어가 그대로 박혀 있는 것이 증거입니다.
왜 못
걸렀나
출력 정리 함수 clean_line(app/core/wording.py:32)은 HTML 태그와 양끝 따옴표만 걷어냅니다. [규칙 준수] 블록이나 (※ …) 주석을 막는 장치가 없습니다.
조치
결함 2를 고치면 원인이 사라집니다. 다만 solar-pro는 단순 인사 요청에도 “(간결하게 … 구성해보았습니다)”를 덧붙이는 성향이라, clean_line에 메타 블록 제거를 안전망으로 추가하는 것을 권합니다.
결함 02 치명 담당: AI 결함 1의 근본 원인

QA 환각 판정의 정밀도가 0/35입니다

증상
생성한 4개 노드가 전부 환각으로 판정돼, 노드마다 재생성 2회를 더 돌고도 해결되지 않은 채 qa_flags 4건이 응답에 실려 나갔습니다. 대사 LLM 호출이 4회 → 12회로 늘고 생성이 9.6초 걸렸습니다.
실측

플래그 근거가 된 “근거 밖 표현” 35개를 분해했습니다.

토큰 종류개수예시
용언 활용형 (서술어)11 세워진 · 복원했으며 · 느껴보겠느냐 · 스며들었고
문체·부사·형용사19 가벼운 · 끝내주니 · 싶으냐 · 이거야 · 터이니
프롬프트에서 역류한 말4 감탄사 · 어말어미 · 3문장 · 근거해
표기 차이1 삼일운동 (원문엔 3·1운동)
실제 사실 오류0 — 참양성 0건
원인
판정 로직(app/scenario/node_schema.py:861-894)의 전제가 “대사의 모든 어휘가 TourAPI 원문에 글자 그대로 등장해야 한다”입니다. 한국어 서술어는 원문에 있을 수가 없으므로, 3~4문장짜리 대사는 예외 없이 걸립니다. 미지지 어간이 3개만 넘으면 플래그라 대사가 길수록 자동으로 확정입니다.
왜 테스트
는 통과
기존 회귀 테스트의 픽스처 대사가 한 문장("운현궁에서 한옥 건축의 흔적을 살펴보거라, 허허.", 7토큰)이라 우연히 임계값 아래였습니다. 실제 LLM은 50토큰을 뱉습니다. 테스트가 검증하지 못한 구간이 정확히 “실제 길이의 정상 대사”입니다.
덤
스톱워드 필터가 조사 제거 전에만 적용됩니다. "도깨비로"는 목록에 없어 통과한 뒤 어간 "도깨비"가 되어 필터를 우회합니다 — 위 실측에 도깨비가 뜬 이유입니다.
조치
① 즉시: 환각 판정을 재생성 트리거에서 떼고 경고 로그로만 남깁니다. node_schema.py의 주석이 이미 “게이트가 아니라 경고 로그용”이라고 못박아 뒀는데 qa_graph가 게이트로 배선한 상태입니다 — 설계 의도로 되돌리는 겁니다. 이것만으로 결함 1이 사라지고 호출이 12회 → 4회로 돌아옵니다. ② 이후: 판정을 “검증 가능한 주장”(연도·수치·고유명사)만 보도록 재작성하고, 오늘 뽑은 실제 대사 4건을 골든 픽스처로 박아 회귀를 막습니다.
결함 03 높음 담당: 앱 + 서버

마법사에서 고른 조건 4개가 서버로 가지 않습니다

증상
입력확인 화면이 시간·동행·난이도·취향을 표로 보여 주지만, 생성 요청에는 transport·wishlist·budget·no_meals만 담깁니다. 사용자가 “반나절 / 가족 / 어려움 / 역사”를 골라도 결과가 동일합니다.
원인
앱의 explore_draft.dart에 “서버 미지원 필드라 로컬에만 보관”이라고 적혀 있는데, AI는 2026-08-18에 duration·companion·difficulty·tags·use_fixed_script를 모두 받도록 이미 열어 뒀습니다. 앱 쪽 정보가 낡았습니다.
주의
서버 ValidationPipe가 whitelist: true라, 앱이 보내도 서버 DTO에 필드가 없으면 조용히 잘려 나갑니다. 앱·서버를 함께 고쳐야 합니다.
연쇄
headcount도 같이 누락됩니다. AI에 companion → 인원수 변환이 있는데 입력이 안 오니 예산 게이팅이 항상 1인 기준으로 계산됩니다.
결함 04 높음 담당: AI 설정

식음 노드가 한 개도 생기지 않아 예산 입력이 무의미합니다

증상
no_meals=false, budget=30000으로 생성해도 식당·카페가 0개입니다.
실측
INFO | app.scenario.generator | 거리순 시나리오: 후보 30 →
      관광 4조각 + 식음 0 (반경 2000m, 대사=LLM)
원인
app/config.py:113의 scenario_food_per_route 기본값이 0(no-op)이고, .env.example에도 이 항목이 없습니다. budget은 식음 가격대 선택 외에는 쓰이는 곳이 없어서, 앱의 예산·식음 UI 전체가 결과에 영향을 주지 못합니다.
조치
DOKKAEBI_SCENARIO_FOOD_PER_ROUTE=2를 .env와 .env.example에 추가하면 살아납니다. 켜기 전에 결함 5의 kind 미전송을 먼저 처리해야 식음 노드에서 엉뚱한 대사가 안 나옵니다.
결함 05 중간 담당: 앱 잠복 — 기능 켜는 순간 발현

대화 API 호출에 갈림길·노드종류 정보가 빠져 있습니다

증상
앱의 dialogueTurn이 branch·kind·region_id·player_state를 보내지 않습니다.
영향
branch — AI는 시나리오를 들고 있지 않은 무상태 서비스라, 앱이 갈림길 정보를 실어 줘야 분기를 인지합니다. 지금은 with_branching이 꺼져 있어 안 터지지만, 켜는 순간 갈림길 대화가 깨집니다.
kind — 식당·카페 노드에서도 “기억석 조각을 찾아라” 대사가 나갑니다. 결함 4를 해결하면 바로 발현됩니다.

정상 확인된 것

결함만 보면 전체가 망가진 것처럼 읽히지만, 실제로는 뼈대가 모두 돌아갑니다.

POST /v1/scenarios 200 · 9.6초 · 노드 4개 생성
POST /v1/dialogue/turn 200 · 1.3초 · 대사·선택지 정상, 유출 없음
GET /v1/search 200 · TourAPI 실키로 “경복궁” 검색 성공
GET /v1/nearby 200 · 0.6초 · 거리순 POI + 한 줄 요약
위시리스트 앵커 지정 장소가 코스에 강제 포함됨
이동수단 walk / car 반경 산출에 정상 반영

참고로 /v1/dialogue/turn의 대사는 깨끗합니다 — “여기가 바로 도성의 시간을 지키던 보신각터니라. 종소리 울리며 새벽을 알렸다는구먼. 허허.” 이 경로만 QA 루프를 타지 않기 때문이고, 결함 1·2가 QA 루프에서 비롯됐다는 또 하나의 증거입니다.

그 외 확인된 것

  • 검색 응답 형태 확인 필요 — 앱은 최상위 배열을 파싱하는데 AI는 {"candidates": [...]}를 줍니다. 서버가 벗겨 주는지 확인이 필요합니다 (server 레포는 이번 점검 범위 밖).
  • 위시 앵커가 반경 안인데도 “반경 밖”으로 처리 — 경복궁은 출발점에서 1.03km(반경 2km 안)인데 후보 목록이 거리순 30건으로 잘려 매칭에 실패합니다. 원문 조회 키는 보존되어 대사 품질에는 영향이 없습니다.
  • 앱이 qa_flags를 파싱하지 않음 — 생성 품질 경고가 앱까지 오지 않습니다. 서버에서만 쓸 값이면 현행 유지로 괜찮습니다.

재현 방법

.env에 DOKKAEBI_LLM_PROVIDER=upstage와 실제 키가 들어 있어야 합니다. mock으로는 결함 1·2가 재현되지 않습니다.

uvicorn app.main:app --reload

curl -X POST localhost:8000/v1/scenarios -H 'Content-Type: application/json' -d '{
  "user_id":"guest",
  "start":{"lat":37.5703,"lng":126.9856},
  "end":{"lat":37.5547,"lng":126.9707},
  "transport":"walk","wishlist":[],"budget":30000,
  "no_meals":false,"region":"종로","with_dialogue":true }'

응답의 node_sequence[].npc_dialogue와 qa_flags를 보면 결함 1·2가, 서버 로그의 QA 플래그 … 경고 줄에서 재생성 횟수가 그대로 보입니다.
